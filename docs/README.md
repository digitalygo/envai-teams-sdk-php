# Contracts: shared OpenAPI and event types for Envai AaaS

This package holds the shared contracts imported or generated by both the
Laravel control plane and the Go execution plane. Two files exist:
`events.json` (ATP event envelope and families) and `openapi.yaml` (the full
HTTP surface for both planes). The protocol itself is defined in
`docs/agent-team-protocol.md`; this package mirrors it.

## events.json

JSON Schema (draft 2020-12) for the ATP event envelope and all event
families. It is the single source of truth for the event stream shapes,
mirroring sections 4, 7, 8, 9 and 10 of `docs/agent-team-protocol.md`.

The envelope is `{v, id, seq, ts, chat_id, turn_id, agent, type, data}`:
positive `seq` values order replayable events while the chat runtime remains
resident; wire-only `ping` uses `seq: 0`. `turn_id` is the nullable orchestrator
completion id `cmpl_<ulid>` the event belongs to (null for `ping`), `agent` is
null for `turn.*`, `ping` and `approval.response`, and `type` discriminates
`data`. The schema defines the
shared `Envelope`, `Agent`, `Usage` and `ToolKind` shapes plus one named
schema per event type (`turn.*`, `agent.*`, `approval.*`, `ping`) and a
forward compatible `Event` union: an unknown or future `type` still
validates, so clients ignore what they do not know (additive-only extension
within `v`). The `Usage` object carries `input_tokens`, `output_tokens`,
`cost_usd`, `duration_ms` and `sprite_ms` on the terminal events; the
terminal turn events also carry the chat lifetime totals (`chat_usage`,
`chat_cost`).

## openapi.yaml

OpenAPI 3.1.0 contract for the full HTTP surface of both planes, served under
the canonical `/api/v1` prefix (legacy `/v1` paths are not aliases). The
execution plane (Go gateway) exposes the chat based Agent Team Protocol
surface: sending a message to a chat, the SSE events stream with `?after=<seq>`
replay, the `/cancel`, `/steer`, `/tool-output` and `/approval` control
endpoints, the `/fork` and `/restore` endpoints and `GET /api/v1/capabilities`.
The control plane registers the user-scoped client tools
(`/api/v1/tools` CRUD) whose names authorize client tool
visibility when listed in `agent_definitions.external_tools_enabled`.
The chat is
the only execution entity: one chat holds one history and hosts many turns,
with no parallel run or session lifecycle. The control plane (Laravel)
exposes workspaces, chats, completion metadata, agent definitions, teams, the
LLM model catalog, api keys, image operations, signed artifacts, provider
webhooks, the workspace files api (read, write, download and pdf conversion of
the workspace fake filesystem: wiki, skills and `MEMORY.md` are plain files
under it) and the public JWKS endpoint. Every endpoint carries request and
response schemas; the events stream references `events.json` through external
`$ref` for the envelope and per-type payloads. Auth is the long lived api key
jwt (`envai_sk_<ulid><jwt>`) sent as a bearer token and validated against the
control plane JWKS; the control plane also accepts a Laravel web session
cookie.

## Client tools

Client tools are user-scoped resources registered on the control plane
(`POST /api/v1/tools`), shared across all workspaces of the owner. An agent sees
a client tool only when its name is in `agent_definitions.external_tools_enabled`
and the tool is registered by the same user; no derived restrictions apply. At
runtime the execution plane reads the registry directly from Postgres
(`user_tools`) with a 60 second cache per user.

When an agent calls a client tool the gateway emits `agent.tool.request` with
`kind: "client"` and an EdDSA signature (same Ed25519 key family that signs the
api key jwt, `kid` from `/.well-known/jwks.json`) over the canonical payload
`call_id + "\n" + tool_name + "\n" + canonical_json(args)` per RFC 8785. The
client verifies, executes locally and posts the output to
`POST /api/v1/chats/{chat_id}/tool-output`, which answers `204` and echoes
`agent.tool.result`; resolution is at most once by `call_id` during the active
turn rather than transparently retry-safe (409
`tool_already_resolved`/`tool_timed_out`, then 404 after the terminal event;
404 also covers unknown or cross-chat ids) and
auto-resolves with `tool_timeout` past the per-tool deadline (default 120
seconds, max 600). `GET /api/v1/capabilities` announces the `client_tools`
feature and the `agent.tool.request`/`agent.tool.result` event types.

## Relationship to the other contracts

- `docs/openapi.yaml` is the historical control-plane-only spec: it documents
  the Laravel HTTP surface (workspaces, chats, agents, teams, models, api
  keys, JWKS, image operations). `packages/contracts/openapi.yaml` supersedes
  it as the single combined contract.
- `docs/agent-team-protocol.md` is the source of truth for the protocol:
  transport, envelope, endpoints, event taxonomy and state model.
  `events.json` and `openapi.yaml` derive from it.
- `packages/contracts/openapi.yaml` documents both planes, and
  `packages/contracts/events.json` is the event source of truth, referenced
  by the events endpoint.

## Generation

Generate clients with `openapi-generator` or `oapi-codegen` in both apps.
The event stream schema lives in `events.json` and is referenced from
`openapi.yaml` through external `$ref` (`./events.json#/$defs/...`), so pass
both files to the generator or map `events.json` with an import mapping.
